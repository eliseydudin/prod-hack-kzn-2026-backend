# Пример импорта билета через Swagger

`flight.pdf` — синтетический PDF с текстовым слоем. В нём нет настоящего бронирования или персональных данных.

1. Откройте Swagger `/api/v1/docs`, выполните **Authorize** под своим аккаунтом.
2. Создайте поездку через `POST /trips/`:

   ```json
   {
     "name": "Проверка импорта билета",
     "startedOn": "2026-12-10",
     "endedOn": "2026-12-13"
   }
   ```

3. Скопируйте `id` созданной поездки в поле `tripId` операции **tickets → preview**. Выберите `flight.pdf` в `file`, не отправляйте `url`. Выполните запрос.
4. Проверьте `issues` и `readyToApply`. Preview не сохраняет данные. Если место не определено, выберите координаты вручную; для неполного времени подтвердите дату и часовой пояс.
5. Откройте **tickets → apply**, выберите **Examples → Авиабилет: SVO → KZN**, укажите тот же `tripId` и выполните запрос. Для другого документа замените точки и даты.
6. В ответе `201` будут точки и перемещение. Повтор того же подтверждения возвращает те же записи без дублей. Созданные записи доступны через обычные маршруты points/transfers/events и на фронте после обновления поездки.

Для гостиницы выберите пример `stay`: в нём одна точка `stay`, время заселения и выселения. Из preview в apply передаются `departure.point` / `arrival.point` или `stay.point`, а не весь ответ целиком.

Все моменты времени в apply требуют смещение (`+03:00`) или `Z`; сервер сравнивает дни поездки по UTC. Готовые JSON-примеры и примеры ответов доступны прямо в OpenAPI. Координаты, расписание и ID из примеров служат демонстрации.
